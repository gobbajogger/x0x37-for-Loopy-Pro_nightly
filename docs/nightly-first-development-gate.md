## Scope of the receipt waiver

The 2026-10-25 decision above removes separate paperwork receipts as NIGHTLY qualification blockers. It does not transfer third-party rights, change repository licenses, authorize proprietary SDK/toolchain disclosure, or turn missing evidence into PASS. Preserve applicable distribution obligations and author notices. Distinguish a missing receipt document from an absent build or failed/unrun check: consume existing exact-input evidence where available instead of demanding a duplicate receipt or rebuild. Source/history and BUILD_ONLY work may continue without claiming an installable or published result.

Standing channel approval is not permission for every worker to publish. Apply the latest action-specific authority and sole-publisher ownership. Hardware validation and separate production promotion remain distinct. This documentation change neither changes runtime admission nor publishes a candidate.

## Mechanical decision

- **NIGHTLY history eligible:** truthful source/build evidence, remote SHA and stage status; no hardware requirement.
- **NIGHTLY source/UI merge eligible:** reviewed fresh PR, applicable native npm/browser/static/negative checks; no hardware requirement.
- **NIGHTLY installable DEV eligible:** exact matching real build artifact, independent safety review, complete model/controller/hash/backup/installer automated PASS, and hosted bytes whose size and SHA-256 match. A distribution license and a corresponding-source check are not eligibility gates. A missing native-build receipt does not reject a nightly candidate. A present native-build receipt which is not PASS with evidence still rejects. Hardware verification is not needed. Failure of an eligibility gate => history only.
- **PRODUCTION firmware/behavior eligible:** all applicable software requirements **plus** same-byte per-model owner's real-device PASS and separate production approval. Missing => PRODUCTION HARDWARE GATE PENDING, production main unchanged.

Never bypass a safety-refused Git write, force-push, silently update shared branches, fabricate tests/device proof, flash hardware, expose private inputs or overwrite another worker's lane.

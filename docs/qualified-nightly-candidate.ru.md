# Подготовка тестовой сборки NIGHTLY

Обычная команда `npm run build` создаёт предварительный сайт с пустым каталогом.
Отдельная команда `npm run prepare:candidate` принимает проверенный каталог и
подтверждения проверок и создаёт локальный сайт. Она не публикует Pages, не
сливает исходники, не отправляет Git и не записывает устройство.

Назначенный единственный владелец публикации передаёт `--catalog`,
`--qualification` и `--out` в указанном порядке. Каталог результата должен быть
новым и находиться вне репозитория. Точный синтаксис выводит
`node scripts/render-qualified-nightly.mjs` без аргументов.

## Каталог и точные входные данные

Каталог использует схему 1 с `versions` и `models`. У версии обязательны
`status: dev-checked`, `config: dev`, `hardware_tested: false`, метка
DEV / HARDWARE TEST — DEVICE NOT TESTED, полные `source_commit` и `source_tree`.
Запись Elite/Pro содержит точный продукт `_900`, размер, SHA-256, неизменяемый
HTTPS `pkg` с адресацией по дайджесту и `controller_sha256`. Поле `latest`
указывает на квалифицированную версию. Ранее проверенные версии передаются
вместе с новой; генератор не угадывает и не удаляет историю действующего
каталога. Непригодные для установки результаты остаются в отдельной истории.

Объект подтверждений содержит `schema: 1`, `installer_sha256` и `packages`,
индексированные SHA-256 пакета. `installerFingerprint()` включает реальные
HTML/библиотеки установщика, генератор и файл закреплённых старых пакетов.
Изменение этих входов требует актуальной проверки. Подтверждение пакета повторяет
`source_commit`, `source_tree`, `product`, `size`, `url`; указывает принятую
firmware-интеграцию `integration` (`ref: nightly`, коммит, идентичное дерево,
`evidence_url`); содержит `controller` и измеренные `budgets`
(`app_code_free`, `ram_free`, `pool_free`). Минимум свободного пула — 8192 байта.

Новые кандидаты используют встроенный контроллер: `controller_strategy: bundled`,
точный `controller_size` и `controller_sha256`; стратегия, размер и хеш в
подтверждении должны совпадать. Только два ранее опубликованных пакета с точными
идентичностями из `scripts/legacy-controller-packages.json` сохраняют режим
`owner-supplied` с проверяемым локальным контроллером. Это исключение сохраняет
доступность старых пакетов и не разрешает новые пакеты с пустым слотом.
Байты прошивки и контроллера не копируются в Git сайта.

## Проверки и отменённые формальные требования

Все восемь проверок `requiredGates` требуют PASS и неизменяемую ссылку
`evidence_url`: `package-integrity`, `model-controller`, `memory-flash`,
`host-regressions`, `backup-restore-readback`, `interruption-recovery`,
`ota-target-binding`, `independent-qa`.

По [решению владельца от 2026-10-25 и его действующей области](nightly-first-development-gate.md#scope-of-the-receipt-waiver)
отдельные формальные подтверждения `distribution-license` и
`corresponding-source` не являются обязательными полями квалификации.
Отсутствующее подтверждение `native-build` не отклоняет кандидата; присутствующее
должно содержать PASS и доказательство. Поля `corresponding_source` и `notices`
сами по себе не принимают и не отклоняют кандидата. Отсутствие документа не
записывается как PASS.

Используйте уже существующие доказательства для тех же точных входов, не требуя
дубликата документа или повторной сборки. Решение не передаёт чужие права,
не меняет лицензии и не превращает отсутствующий пакет или неуспешную сборку
в проверенный результат. Сохраняются применимые условия распространения,
авторские уведомления, реальные доказательства сборки/пакета и независимая
проверка. Генератор проверяет структуру подтверждений; он не удостоверяет
подлинность чьего-либо PASS и не заменяет рецензента. Синтетические тестовые
подтверждения не разрешают публикацию.

## Создание сайта и проверка байтов

Перед созданием сайта генератор повторно скачивает каждый пакет по HTTPS без
перенаправлений и проверяет реальные размер, SHA-256 и модель. Поток ограничен
утверждённым размером до выделения полного буфера; ответы без потокового reader
отклоняются. Неизвестные поля схемы отклоняются. Сайт получает только явно
разрешённую публичную проекцию каталога. Полный `qualification.json` остаётся
частным входным документом и не публикуется.

Для `bundled` генератор и браузер расшифровывают и проверяют реальный встроенный
контроллер: раскладку SMK, CRC установленного файла и вложенного приложения,
ABI/заголовок, CRC контроллера, стёртое заполнение слота 64 КиБ, точный размер
и SHA-256. Только после проверки браузер предлагает проверенный Blob, скрывает
отдельное поле контроллера и повторяет проверку перед установкой. Совмещённые
байты передаются без изменения. Отсутствие или несовпадение контроллера блокирует
установку. Для закреплённых старых пакетов обязателен локальный контроллер
с точным хешем. В обоих режимах сохраняются защита от смены выбора во время
проверки, подтверждение DEV, модель, резервное копирование/восстановление и OTA.

## Продолжение до результата

Независимый рецензент проверяет созданный сайт и пути установки в браузере.
Единственный назначенный владелец публикации сверяет существующую историю Pages,
обновляет её обычным fast-forward по разрешённому маршруту и проверяет реальные
опубликованные каталог, установщик и хеши скачанных пакетов. Локальная папка,
Git-коммит, публикация Pages и проверка устройства — разные результаты.

Недоступный URL, неуспешный тест или отсутствие обязательных доказательств QA
оставляют затронутого кандидата NOT INSTALLABLE с конкретным владельцем и
следующим действием. Отчёт не завершает незавершённую задачу: принятые действия
продолжаются в рамках действующих полномочий, а независимые исходники и история
обрабатываются параллельно в пределах реальной доступной мощности. Для полностью
проверенного NIGHTLY не нужны предварительный аппаратный PASS и новое разрешение
в чате на каждую сборку. Для production требуются отдельное разрешение и
проверка тех же байтов владельцем на соответствующем устройстве.

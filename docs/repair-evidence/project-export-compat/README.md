# Portable project revision compatibility

Current firmware d633833ac369f8466bc2563791614206070e87d1 exports canonical pattern stream 3 / sound revision 10 files, while the old browser accepted only 3 / 4. The parser now recognizes explicit pairs (3,4), (3,10), and the separately proven endpoint-layout pair (6,10). It returns the actual header versions and preserves every payload byte. It does not interpret sounds, infer historical engine identity or migrate data. Unknown pairs, header flags, damaged CRCs and wrong lengths remain refused.

Firmware VALIDATE remains before any sample mutation or project adoption. A protocol-peer regression confirms a stream-3 receiver rejects a stream-6 import without a sample write or COMMIT. Browser acceptance of a known container is not proof that every keyboard can adopt it.

The two compressed JSON fixtures contain synthetic C-generated bytes, not captured user projects or samples. The current fixture comes from clean d633 source; the endpoint fixture records the uncommitted source blobs of the recorder unit. Both used real project_capture_stage/header bytes and passed actual project_validate_stage and project_file_validate with SMK + WOBBLE1 + DEV1. Both files are 36428 bytes (36396-byte project payload). Generator C/shell sources are retained under generator/. Their command expects the maintained firmware test harness in its source checkout; no private SDK or binary is included here.

The endpoint fixture proves the raw portable (6,10) layout contract only. Endpoint firmware source, native builds, migration policy and device qualification remain the recorder owner's separate gates; this browser patch grants no snapshot/whole-sound-lock or per-voice engine migration claim.

Before/after execution imports the unmodified old parser (Git blob c9aae930f79ccdef2d03978fbf3cf42045baea06) and each repaired module. Both actual fixtures were rejected before; both repaired copies preserve the exact bytes through export/bundle/read. Existing legacy (3,4) tests remain. Each copy's project tests pass 33/33; firmware projects-page tests pass 7/7. Website build, complete npm (including 43 edge regressions) and source-provenance checks pass. Logs and hashes are in receipt.json.

No firmware C/DSP/UI/schema, device command, native build, GUI, headless browser, public deployment or merge occurred in this lane. The changed behavior is exercised through actual frontend functions and generated source parity; full physical/device/browser qualification is not claimed. A duplicate local generator prototype failed on an unused diagnostic macro before producing data; no fixture or pass result came from it. The product fixtures supplied by the recorder unit are the verified inputs used here.

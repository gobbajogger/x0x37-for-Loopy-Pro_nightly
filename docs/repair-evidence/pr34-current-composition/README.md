## Exact Projects boundary

Accepted pairs are `(3,4)`, `(3,10)`, `(6,10)` and `(6,11)`. The final pair is
the actual native144 `TAGGED_SOUND=1`, `NOTE_SOUND=0` producer and must be exactly
36,452 bytes. Protocol QUERY v2 has that same exact size; protocol v1 behavior
is retained. Stream 7 is intentionally unsupported here, despite the donor
module also knowing that optional feature. Streams 4/5 and unknown revisions,
bad headers, lengths, CRCs and reserved fields remain refused.

All high-level container expected-length checks and firmware VALIDATE-before-
sample-write checks remain intact. Consequently old 36,428-byte rev10 files
cannot be imported by the high-level UI into tagged firmware: they fail before
IMPORT, sample changes or adoption. This integration does **not** offer a legacy
bass-identity chooser and does not claim that legacy-import UI works.

The low-level client retains the exact donor's explicitly invoked legacy staging
exception only for protocol2, stream3/6, rev10 and 36,428 bytes. VALIDATE returns
error9 explaining that both engine identities need explicit confirmation; ABORT
preserves the live project/samples. The low-level ADOPT_BASS75 helper requires
literal `confirmed: true`, two bounded engine choices and no dual Miami. No
automatic/UI import path invokes it. Firmware remains the semantic authority.

## Fresh producer and test inputs

`tests/fixtures/project-v6-sound11-wbl{0,1}.json` contain synthetic, sample-free
exports freshly generated by the exact144 C storage test. Each carries the
producer SHA, source-test blob, configuration, length and decompressed SHA-256.
No private user samples, SDK, toolchain, firmware or controller binaries are
included. The generation command is:

```
BASS_NOTE_FLAGS=-DX0X_BASS_NOTE_SOUND=0 BASS_TAG_OUTPUT_DIR=<private-scratch-output> \
  sh tests/host/bass_tagged_storage_test.sh
```

It ran from the clean exact144 firmware checkout and passed 1,621 WBL0 and
1,670 WBL1 actual C storage/stage/adoption checks, the 19-check original browser
regression and the tagged Getting Started scenario. Only native wire/flash
boundaries in that host test are substituted; no hardware was accessed.

The unchanged original browser regression is retained under `tests/host/` and
was additionally run against this website module and those fresh raw exports.
`tests/edge-project-tagged-v2.test.mjs` reuses the unchanged historical suite's
stateful synthetic wire peer. It verifies actual C-export container round trips,
occupied sample preservation, exact recovery backup bytes, explicit backup
acknowledgement and VALIDATE-before-sample-mutation/COMMIT. It separately tests
high-level legacy refusal, low-level identity-needed/ABORT and unsupported
schema/protocol/length negatives. The synthetic peer is not firmware or hardware
proof; semantic producer/storage proof comes from the actual C test above.
